# Locust — нагрузочное тестирование RAG API

## Структура

```
tests/locust/
  .env.example          # шаблон переменных окружения
  .env                  # твои данные (не коммитить!)
  config.py             # KB ids, вопросы, константы
  locustfile.py         # точка входа
  requirements.txt
  Makefile
  users/
    user_scenario.py    # сценарий пользователя
    admin_scenario.py   # сценарий администратора
```

---

## Подготовка (один раз)

**1. Установить зависимости:**
```bash
make install
```

**2. Создать `.env` из шаблона и заполнить:**
```bash
cp .env.example .env
```

Что нужно заполнить в `.env`:
- `BOT_SECRET` — токен бота (из `docker/.env`, поле `BOT_TOKEN`)
- `ADMIN_TOKEN` — Bearer-токен администратора (из Redis):
  ```bash
  # в redis-cli
  get admin_token_user:<твой_telegram_id>
  # вернёт токен → вставить в ADMIN_TOKEN
  ```
- KB IDs и коды — создай многоразовые инвайт-коды без лимита для каждой KB в панели администратора

**3. Заполнить вопросы в `config.py`:**

В разделе `QUESTIONS` для каждого отдела указать пары `(оригинал, перефразировка)`:
```python
"IT": [
    ("Как настроить VPN?", "Как подключить корпоративный VPN?"),
    ...
]
```

## Запуск тестов

### С веб-UI (рекомендуется для первого запуска)
```bash
make ui
# открыть http://localhost:8089
# ввести кол-во пользователей и spawn rate → Start
```

### Smoke-тест (5 пользователей, 30 сек)
```bash
make smoke
```

### Load-тест (20 пользователей, 2 мин)
```bash
make load
```

### Stress-тест (50 пользователей, 3 мин)
```bash
make stress
```

### Только пользователи (без админа)
```bash
make users-only
```

### Только админ
```bash
make admin-only
```

### Кастомный запуск
```bash
make run USERS=30 SPAWN=3 DURATION=90s
```

## Сценарии

### RagUser — обычный пользователь (80% нагрузки)

Симулирует пользователя который общается через бота:

| Шаг | Описание | Вес |
|-----|----------|-----|
| 0 (on_start) | Регистрация по инвайт-коду | 1 раз |
| 1 | Получить список доступных KB | 2 |
| 3 | Задать вопрос — холодный (кэш-мисс) | 10 |
| 4 | Задать похожий вопрос (кэш-хит) | 5 |
| 4.1 | Запросить документ-источник по presigned URL | 3 |
| 5 | Просмотр истории диалога | 3 |

### RagAdminUser — администратор (20% нагрузки)

Выполняется последовательно (SequentialTaskSet):

| Шаг | Описание |
|-----|----------|
| 1 | Статистика (dashboard) |
| 2 | Создать KB |
| 3 | Загрузить документ |
| 4 | Проиндексировать документ |
| 5 | Выдать доступ пользователю |
| 6 | Создать инвайт-код |
| 7.0а | Плейграунд — холодный вопрос |
| 7.0б | Плейграунд — похожий вопрос (кэш-хит) |
| 7 | Удалить документ |
| 8 | Удалить KB |
| 9 | Удалить пользователя |

## Интерпретация результатов

### Ключевые метрики

| Метрика | Что означает |
|---------|-------------|
| **RPS** | Запросов в секунду — общая пропускная способность |
| **Avg / Med** | Среднее и медианное время ответа (мс) |
| **95%** | 95% запросов ответили быстрее этого значения |
| **Failures %** | Процент ошибок — должен быть 0% |

### Ожидаемые latency (локально, Ollama)

| Запрос | Ожидаемо |
|--------|----------|
| `/ask` холодный (кэш-мисс) | 3–12 сек (зависит от LLM) |
| `/ask` кэш-хит | < 1 сек |
| Остальные эндпоинты | < 100 мс |

### Узкое место

При локальном Ollama основное узкое место — LLM inference. Ollama обрабатывает запросы последовательно по умолчанию. Для параллельной обработки:
```bash
OLLAMA_NUM_PARALLEL=2 ollama serve
```

На продакшн-окружении с облачным LLM (OpenRouter и др.) latency `/ask` будет значительно ниже.
